# 瓶颈与最小割（`bottleneck`）

> 领域：通用。工作结构：`generic_graph`。

```yaml
id: bottleneck
name: 瓶颈与最小割
workbench: generic_graph
recognize:
  surface_cues: ["短缺", "被卡脖子"]
  structural_checks: ["容量能估计", "流向清楚"]
  discriminating_test: "加大非瓶颈环节的容量，产出会不会变？会 → 不是瓶颈"
```

**识别特征**：产出被某个环节卡住；问"卡在哪""谁受益"。

**方法步骤**：

1. 画流网络（上游 → 下游，每段容量）
2. 找最小割；价值与议价权流向绑定约束的持有者
3. 估计瓶颈能持续多久（新产能的供给响应）

**合适表示**：流网络（暂用通用图，标准化待补）。

**在原问题里怎么验证**：用实际数据核对：割的容量 ≈ 实际产出。

**适用假设**：容量能估计。

**失效信号**：瓶颈随时间快速移动 → 反馈与动力系统。

**常见陷阱**：把需求增长当成瓶颈。

**例子**：算力扩张被电力和变压器卡住。
