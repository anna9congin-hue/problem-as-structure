# 冷启动与自举（`cold-start`）

> 领域：通用。工作结构：`dependency_graph`。

```yaml
id: cold-start
name: 冷启动与自举
workbench: dependency_graph
recognize:
  surface_cues: ["先有鸡还是先有蛋", "没有记录就拿不到资格"]
  structural_checks: ["画出依赖关系后确实有环"]
  discriminating_test: "把依赖画出来：有环 → 冷启动；没有环 → 只是普通的约束满足"
```

**识别特征**：要 A 才能得到 B，要 B 才能得到 A。

**方法步骤**：

1. 画依赖图，标出环
2. 找环外的入口（中继）：不要求 A、又能产出 A 或 B 的东西
3. 分阶段：先用中继拿到最小的 A，再换 B

**合适表示**：依赖图：节点是要拿到的东西，requires 边，环单独标出。

**在原问题里怎么验证**：中继在原问题里真能产出所需的东西（例如账户确实上报信用局）。

**适用假设**：存在一个不要求 A 的中继。

**失效信号**：所有中继都要求 A → 放松约束或改目标。

**常见陷阱**：把本身就要求 A 的产品当成中继；只凭说法判断有环，没有画出来。

**例子**：零信用建信用；没有业绩记录募资；没有案例拿第一个大客户。
