# 规划与调度（`planning`）

> 领域：通用。工作结构：`dependency_graph`。

```yaml
id: planning
name: 规划与调度
workbench: dependency_graph
recognize:
  surface_cues: ["先做哪个", "期限"]
  structural_checks: ["动作的结果基本确定", "先后依赖能列出"]
  discriminating_test: "动作结果是否基本确定？很不确定 → 转不确定下的决策"
```

**识别特征**：要安排一串动作；有先后、时间、资源限制。

**方法步骤**：

1. 从目标倒推
2. 找关键路径
3. 先排最受约束的动作

**合适表示**：依赖图（动作与前置条件）或时间线。

**在原问题里怎么验证**：按计划执行第一步并核对实际耗时与前置条件。

**适用假设**：动作的结果基本确定。

**失效信号**：动作结果很不确定 → 不确定下的决策。

**常见陷阱**：遗漏隐含的前置条件（证件、审批时间）。

**例子**：搬家与开户的先后安排；项目排期。
