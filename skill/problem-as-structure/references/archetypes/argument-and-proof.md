# 论证与证明（`argument-and-proof`）

> 领域：通用。工作结构：`argument_graph`。

```yaml
id: argument-and-proof
name: 论证与证明
workbench: argument_graph
recognize:
  surface_cues: ["这个说法成立吗", "写论文、投资论点"]
  structural_checks: ["说法能写清楚、能写出证伪条件"]
  discriminating_test: "证据测的量和论断里的量是不是同一个？不是 → 这条证据不能改变判定"
```

**识别特征**：要确认一个说法对不对，或要对外宣称结论。

**方法步骤**：

1. 先找反例（对手先行）
2. 分情况讨论
3. 逐个核实前提；需要形式化的部分交给 Lean 或 SMT
4. 每条论断写覆盖：已核对什么、没覆盖什么

**合适表示**：论证图：论断、依赖（结论 / 方法 / 引用）、验证、预测。

**在原问题里怎么验证**：原文逐字核对、复跑计算、到期结算预测。

**适用假设**：说法能写清楚。

**失效信号**：前提本身是价值判断 → 交给用户；证据测的量和论断的量不同。

**常见陷阱**：把"训练测试不重叠"当成"类型与来源已解耦"；自评当独立检验。

**例子**：某条政策是否适用于我；某篇论文是否推翻了一条文献判定。
