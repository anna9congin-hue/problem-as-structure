# 委托模板：交给其他 agent 的任务

原则：交付质量 ≈ 验证器质量。委托前按下表给任务分类，然后照模板写交接说明。

## 1. 分类

| 类 | 验证器 | 怎么交 |
|---|---|---|
| A：即时、客观、覆盖充分 | 脚本或规则能直接判对错，例如文件类型与标题、子串匹配、单元测试、编号能否解析、对账平衡 | 交给便宜的 agent，附上验证器；允许多试几次 |
| B：有验证器，但延迟长或噪声大 | 结果要等很久才知道，或对错里混着运气，例如预测、回测、A/B 测试 | 不靠多试。交出去之前写下预测和结算日期，到期对账 |
| C：没有外部验证器，或只能按价值裁决 | 没有，例如"是否推翻""选哪个母题""值不值得" | 不整体交出去。拆成 A 类的抽取题交出去，判断留给自己或用户 |

拆分示例：不要问"这篇论文推翻判定 G4 了吗"，而是交出去三个抽取题：主表报告了哪些指标？有没有测选择准确率？给出逐字引语和定位。拿回来以后，由自己判断"这个量是不是论断要的那个量"。

## 2. 交接说明模板

```markdown
# 任务：<一句话>

## 交付物
- <文件路径与格式>（只交这些，不要额外的总结或自评）

## 验证器（交回后由委托方运行；你可以先自己跑）
- 命令或清单：<例如 python3 引语核对.py；file *.pdf；标题与 Crossref 一致>
- 通过标准：<例如 引语 100% 逐字；每个文件都是 PDF 且标题匹配>
- 它测的量：<一句话，确认就是我们关心的量>

## 规则
- 引语逐字复制，并给出定位；元数据只取 arXiv、Crossref、DataCite 的记录
- 不写判定，或者判定单独放一节、标为"未核实"
- 不打印、不写入任何 key
- 遇到拿不到的内容就写"拿不到"，不要用转述或推测补上

## 停止规则
- <例如 每个缺口找到 1 篇或连续 20 篇无变化即停>
```

## 3. 交回之后

1. 先跑验证器，不通过的部分退回，或者自己补。
2. 通过的部分记为证据，`verified` 按验证器结果填。
3. 接手者写的判定只算候选，按"论证与证明"母题自己复核。复核时先写一句：证据测的是什么量，论断要的是什么量。
4. 接手者的自评不能当作 `independent` 检验。
